## 1. 盘点（磁盘真值）

- 8 步：`step_1_topic`（local，输入 topic + target_audience_level）→ `step_2_hook`（analysis）→ `step_3_explain` / `step_4_scene` / `step_5_boundary` / `step_6_takeaway` / `step_7_visual`（generation，其中 step_3 标 `parallel: true`）→ `step_8_output`（fusion）。

## 2. 提示词 ↔ rubric 覆盖映射

记号：**G** = 提示词明文要求；**H** = 只靠人设/间接指望；**M** = 提示词未要求。

|---|---|---|---|

| explanation_text | ① 段数 2–4，每段 1 点 | **G** | 「写2到4段，每段只讲1个点」 |
| | ② 专业词一句话翻译 | **G** | 「必须用时一句话翻译」 |
| | ③ 生活/工作类比，非定义堆砌 | **G** | 「多用生活类比和工作场景，像在给朋友解释」 |

## 3. 端到端干跑（样例主题）

- 样例输入：`topic = "AI 智能体（Agent）到底是什么"`，`target_audience_level = 普通上班族`
- 执行方式：按各步 `prompt_template` 逐段执行（变量真实替换），执行模型 = 本助手。**非 qianwen/zhipu**。

**step_2 → hook_statement**
> 90% 的人把 AI 智能体当成了聊天机器人，其实它真正值钱的地方，是替你把一整条流程跑完。

**step_3 → explanation_text**（开头接 hook，3 段）
> 你可以把它想成一个新来的实习生：聊天机器人是你问一句它答一句，问完活儿还是你干；智能体是你交代一句「把这周的销售数据整理成周报」，它自己去拉数据、做表格、写结论，最后把成品交给你。
>
> 它和以前的自动化工具也不一样。以前的工具像流水线上的机器，只能干设定好的那一步；智能体更像会自己看情况调整的员工——数据格式变了、少了一列，它会自己想办法补，而不是停下来等你修。
>
> 现在真正能稳定用的场景还不多，但「能替你跑完一条流程」这件事本身，已经值得你留意了。

**step_4 → use_cases**
> 如果你是每周要交周报的运营：你在周五下午整理一周的投放数据、写复盘，为什么用到它——把拉数据、做图表、写初稿这一整条流程交给它，你只做最后的判断。
>
> 当你第一次想把 AI 用进日常工作、却卡在「每次都要重新教它上下文」：你在反复向聊天机器人粘贴背景资料，为什么用到它——智能体自己记得住任务上下文和流程，不用你每次重讲一遍。

**step_5 → boundary_notes**
> 适合：工作里有固定重复流程（周报、汇总、巡检）、愿意花时间把流程交代清楚的人。不适合：想要「一句话全自动出成品」的人——现在交付质量还不稳定，关键环节仍然需要人把关；也不适合处理高风险决策（合同、医疗、财务判断），它目前还不成熟。

**step_6 → takeaway_content**
> 一个可立即尝试的小动作：挑一件你每周都要做的重复性工作，把步骤写成 5 行以内的清单发给智能体，看它跑完的成品能直接用的占比——超过一半，这条流程就值得交给它。

**step_7 → visual_content**（3 张）
> 封面：大字「AI 智能体≠聊天机器人」/ 副题「差在替你跑完一条流程」
> 内容图 1：「聊天机器人：问一句答一句，活儿还是你干」/ 配图：对话框 + 打工人
> 内容图 2：「智能体：交代一句，整条流程跑完」/ 配图：流水线各节点自动打勾
> 收尾图：「记住这 3 点就够了」/ 「你踩过哪些坑？评论区聊聊」

**step_8 → final_content**（整合，略去全文——6 个上游字段均入文、无占位符残留、无 `[object Object]`、结尾含互动引导）

### 3.1 rubric 打分

| 产出 | ① | ② | ③ | 裁决 |
|---|---|---|---|---|
| hook_statement | 合格 | 合格 | **勉强**（依赖「AI 智能体」主题词，去掉后「它」指代悬空） | 勉强 |
| explanation_text | 合格 | 合格 | 合格 | 合格 |
| use_cases | 合格 | 合格 | 合格 | 合格 |
| boundary_notes | 合格 | 合格（本轮含「还不稳定/还不成熟」，但属提示词软要求） | 合格 | 合格 |
| takeaway_content | 合格 | 合格 | **勉强**（「超过一半就交给它」阈值可操作但未定义「直接用」的对错标准） | 勉强 |
| visual_content | 合格 | 合格（标题互异） | 合格（按画面写，未抄正文） | 合格 |

## 4. 发现（F1–F7）

- **F1**（P2，提示词措辞）：`boundary_notes`② 用「**可以**说明目前还不成熟」——允许而非必须，与 rubric ②「必须提到不成熟/局限」存在张力。改法：「可以」→「要」。
- **F2**（P3，判据无对应要求）：`takeaway_content`③「可验证对错」提示词未要求。改法：加「写完自检这条能不能被验证对错」。
- **F3**（P3）：`hook_statement`③ 自足性（去掉主题词仍成立）未被要求，属编辑侧判据。
- **F4**（P3）：`visual_content`②「标题不重复」、③「非正文复制」未明文，只靠「每张 1 个点、文字 ≤40%」间接约束。
- **F5**（指向既有台账）：`final_content`③「无 `[object Object]`」是**工程判据**（上游对象被当字符串渲染，N4/N7 同源），提示词层管不到——它在 rubric 里的作用是**症状探测器**，根因在 N4（open）。
- **F6**（回溯修正）：rubric 判据①原文写「**七**个字段都真的被整合」，实为 final_content 的 **6** 个上游 `input_fields`。已校正（§4.5 落文档时按 6 写）。
- **F7**（对齐观察）：`quality_validation_rules` 4 条与 rubric 方向一致但只到「有/无」级别（如「必须有可带走的一条」），不到「可核对」精度；两套并存时以 rubric 为准。
- **F8**（回溯修正，裁决规则）：初稿规则「勉强超过 2 项 ⇒ semantic-marginal」留了空洞——1–2 项 `勉强` 既非 pass（非全合格）也非 marginal。已在 §4.5 校正为全覆盖口径：任一 `不合格` ⇒ fail；全 `合格` ⇒ pass；其余（有 `勉强` 无 `不合格`）⇒ marginal，`勉强` >2 项加重注记「能跑不能交付」。本报告 §3.1 的裁决按校正后口径成立。

## 5. 结论

1. **提示词整体质量好**：7 段都有输出围栏（「只输出 X」）、`{{变量}}` 契约清晰、`config` 带示例与格式参数；21 条判据 13 条明文覆盖，`explanation_text`/`use_cases` 达到判据级对齐。
2. **缺口集中在 5 条判据**（1 个 H 重灾区 boundary② + 2 个 M + 2 个 H），都有明确改法（F1–F4）；F5 不归提示词管，归 N4。
3. **干跑裁决 `semantic-marginal`**，但分数不是重点——重点是「提示词没要求的判据，产出就会悬空」这一因果链在 §2 里可逐条对照。
4. **本审计不替代真机**：真 AI 语义质量仍需 L2 真实回复 + §4.5 rubric 人工判定（判据本体见 `docs/REAL_MACHINE_REGRESSION.md` §4.5）。
