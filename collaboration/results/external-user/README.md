# 外部用户试用记录（记录格式说明）

> 这里是**第一个外部用户**的试用记录存放处。
> 每一次试用一个文件，文件名：`EXTERNAL-USER-<名字>-<YYYY-MM-DD>.md`。

---

## 1. 这个目录为什么单独存在

真机回归（L1/L2）证明的是「**我们的代码**在真实站点上还成立吗」。
它证明不了「**产品**对**没参与开发的人**成立吗」——这两件事需要的证据完全不同：

| | 真机回归（L1/L2） | 外部用户 |
|---|---|---|
| 谁执行 | 我们自己 | **没用过这个产品的人** |
| 能不能照着说明书做 | 能（我们太熟了） | **不能**——说明书有歧义就是缺陷 |
| 测的是 | 代码与站点 DOM 的契约 | **产品**（含说明书、报错文案、首次上手） |
| 结论 | 「选择器还命中吗」 | 「这东西我会不会用」 |

路线 A / 路线 B 的决策门禁缺的正是最后一环（见 `docs/REAL_MACHINE_REGRESSION.md` §7），
所以这一栏的记录**不能由我们自己代写**。

> **怎么把这一场跑起来**：见
> [`docs/EXTERNAL_USER_SESSION_RUNBOOK.md`](../../../docs/EXTERNAL_USER_SESSION_RUNBOOK.md)
> ——那是**主持人**用的操作指南（准备什么、交付什么、现场看什么、最后写什么）。
> 本目录只负责**记录本身**的格式。

---

## 2. 记录格式

用 [`TEMPLATE.md`](TEMPLATE.md) 复制一份改就行。字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| 试用者 | 是 | 名字或代号。**不写联系方式** |
| 日期 | 是 | `YYYY-MM-DD` |
| 浏览器与版本 | 是 | 例如 `Chrome 141` |
| 使用的站点 | 是 | 例如 `qianwen.com` |
| 界面语言 | 是 | `中文` / `English` |
| 卡在哪一步 | 是 | 用问卷第 1 题的选项字母（A～F），或自己写 |
| 完成了什么 | 是 | 实际做到了哪一步，**别夸大** |
| 现场报错 | 有就写 | **原样抄**，不要转述、不要美化 |
| 截图 | 可选 | 放同目录，文件名里带日期 |
| 有用吗 | 是 | 问卷第 3 题，原话最好 |
| 备注 | 可选 | 任何你想说的 |

### 判定口径

- 「完成」= AI 那边**真的回话了**，而且回复里**包含**「你好，Prompt Pack 冒烟自检通过。」
- 只是「提示词发出去了」不算完成（那是 D 类，不算 F 类）
- 一次就成功（F 类）**要特别写清楚**：我们至今没在真机上跑通过整条链路，
  所以一次成功本身是**待核实的异常**，不是「没问题了」

---

## 3. 写完之后

1. 把文件放进本目录
2. 在 `docs/REAL_MACHINE_REGRESSION.md` §6.2 的缺口 #5（真实发送链路未验证）里
   附上这次记录的路径——**跑通之前不许把 #5 标成已关闭**
3. 如果记录里暴露了产品缺陷，另开一个工单，不要直接改代码

---

## 4. 隐私红线

- 记录里**不写**账号、密码、手机号、邮箱、公司名
- 截图里如果出现聊天内容，**先遮住**再放进来
- 试用者自己的聊天内容不要粘进记录里——只描述「发生了什么」
