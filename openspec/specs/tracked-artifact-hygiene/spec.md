## Requirements

### Requirement: 机器本地快照不得被跟踪

内容描述「生成它的那台机器」的自动生成产物 SHALL NOT 进入版本库。

判定标准（须能从仓库内证据判定，不依赖主观判断）：产物同时满足下列两条即为机器本地快照——

- 数据源是 gitignored 的本机状态文件（如 `logs/session_registry_state.json`、
  `logs/collaboration_state.json`），或产物由这些状态派生；
- 产物内容含生成时间戳，且其中的计数/枚举反映的是本机而非仓库的事实。

由**同一生成机制写入同一目录**的产物，即使某次输出为空结果、不含计数与时间戳
（如测试路径写出的空摘要），也按本条处理：判定依据是产出机制与落点，不是单次内容。
否则同一机制会有部分实例被跟踪、部分不被跟踪，而这种不一致没有任何人能解释。

理由：这类产物一旦被跟踪，任何人在自己机器上跑一次生成命令就会覆写库里的共享视图，
而 diff 形如一次正常数据刷新，评审无法从 diff 本身看出信息丢失。

#### Scenario: 生成器重跑后不得回流索引

- **WHEN** 在已 untrack 的工作区执行一次会刷新该摘要的 CLI 命令
- **THEN** 文件仍在工作区原路径生成（生成器行为不变）
- **AND** `git status` 不显示该文件为未跟踪或已修改
- **AND** `git add -A` 后该文件不进入暂存区

#### Scenario: 已有的本机快照被 untrack 时内容不丢

- **WHEN** 从索引移除一个已跟踪的本机快照
- **THEN** 工作区中的文件内容保持不变
- **AND** 移除动作之后该文件仍可被本机读取，只是不再参与版本管理

### Requirement: 忽略规则须覆盖全部实例而非逐条列举

针对同一类自动产物的忽略规则 SHALL 使用能覆盖该类全部实例的通配写法，MUST NOT 依赖逐条
列举具体文件名。

「全部实例」包含该类产物的**所有后缀变体**（`_latest` / 日期戳 / `_test` 等）。
仅按最常见的后缀写通配，会把原本被单独排除的其他后缀实例漏出排除面——实测中替换逐条规则后，
`AGENT_DISPATCH_ORDERS_test.md` 就从「被忽略」变成了「未跟踪可见」。

理由：逐条列举的失效方式是静默的——新增一个同类产物时不会报错，只会被意外跟踪；
等到有人 `git add -A` 才发现，而那时错误的快照已经在库里。

#### Scenario: 新增同类产物自动被覆盖

- **WHEN** 生成器产出一个此前不存在的、同属该类的新摘要文件
- **THEN** 该文件命中既有忽略规则，`git status` 不显示它
- **AND** 无需为此修改忽略文件

#### Scenario: 替换逐条规则不缩小既有排除面

- **WHEN** 把逐条列举改为通配
- **THEN** 原逐条规则覆盖的每一个实例，在改后仍被忽略
- **AND** 该项须逐实例复核，不得以「通配看起来更宽」推定

#### Scenario: 规则的完备性可被一次性核验

- **WHEN** 对已跟踪文件集合逐个执行忽略判定
- **THEN** 属于该类产物的已跟踪文件数量为零
- **AND** 判定 MUST 使用能反映规则的查询方式——`git check-ignore` 默认跳过已跟踪文件，
  对受跟踪集合直接调用它必然全部返回未命中，该结果不能用于判定规则覆盖性
