在写任何**手册 / 检查清单 / 备料清单 / 结论汇总**之前，必须先在仓库里核对将要引用的每一个**文件路径、脚本名、编号、目录**是否真实存在；核对不到就写「不存在 / 待建」，**不得凭印象写出来**。

**Why:** 2026-11-02 的 L2/W-D2 会前备料清单复核中发现，此前给出的 4 条备料里有 2 条在仓库中**查无此物**：

- 手册 `docs/EXTERNAL_USER_SESSION_RUNBOOK.md` —— 不存在（`docs/` 下只有 `ALERTING_RUNBOOK.md`）
- 观测器 `chrome-extension/tests/real-machine/l2-send-observer.mjs` —— 不存在（该目录只有 `dom-contract-probe.mjs`）
- 「缺口 #5『回复等待链路』」—— 全仓检索零命中；对照 `docs/REAL_MACHINE_REGRESSION.md` §6 后确认它其实是 **#1/#2**

这类错误写进清单会直接误导下一步动作（让人去打开一个没有的脚本、按错编号去查表），而且**不会报错**，最难发现。

**How to apply:**
- 落盘前先 Glob 目录 + Grep 关键字（含中文关键词），拿真实命中列表再写
- 区分三类状态：**已核实存在**（写路径）/ **不存在**（明写「不存在，尚未编写」）/ **口径待确认**（标注唯一事实源文件）
- 编号类事实（缺口号、章节号）必须回查**上游唯一事实源文档**（如 `docs/REAL_MACHINE_REGRESSION.md` §6），不要沿用对话历史里出现过的编号
- 已有完整文档体系的项目**不要再新建第二份全貌文档**；新文档只做索引或专项，并指向既有事实源
- 与 `feedback_validator_false_positive.md`（工具误报）方向相反：本条针对**自己臆造**，那条针对**工具报错**
