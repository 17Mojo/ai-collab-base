## 事实

- **2026-10-23 起推进的 P1 方向（工单 `TASK-P1-DISPATCH-MODEL-FALLBACK-001`）**：派单链路要做到三件事——
  1. **模型降级**：指定模型不可用时，自动降级到**模型池中的下一个候选**继续投递，而不是直接失败；
  2. **投递回执落盘**：投递过程与结果要有可追溯的回执文件；
  3. **报告口径分离**：报告里必须区分「**请求的模型**」与「**实际用的模型**」。
- 涉及面：派单投递脚本、模型可用性检查脚本、CodeArts 适配器（具体路径见当次工单，不在本记忆重复）。

**Why**: 指定模型不可用会让派单链路在无提示的情况下断掉；没有「实际用的模型」这一列，事后无法判断失败是模型不可用、降级未生效，还是别的环节。降级 + 回执 + 双模型口径是同一件事的三个侧面——可观测性。

**How to apply**:
1. 排查派单/投递失败时，先看报告中请求模型与实际模型是否分离、是否发生过降级，不要只看「指定模型」。
2. 涉及派单可用性的改动，验收要同时覆盖「能检测模型不可用」「能降级到下一候选」「回执落盘可解析」三项，缺一即为未完成。
3. 引用这条目标时注意它是 2026-10-23 启动的在途方向，具体任务状态以 `collaboration/tasks/` 与 `collaboration/results/` 的工单/结果文件为准。
