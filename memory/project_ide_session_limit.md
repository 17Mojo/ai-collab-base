description: IDE 限制同一工作区同时活跃的 Agent 会话最多 3 个，超限报「并发会话数已达上限(3个)，请关闭部分会话后重试」；kernel /session 元数据可列全部会话但看不出哪些在运行
type: project
from: Agent
---

IDE 对**同一工作区**同时活跃（打开/运行中）的 Agent 会话有**上限 3 个**。超过后任何新动作都会被拒并提示：

> 并发会话数已达上限(3个)，请关闭部分会话后重试。

- **历史会话不计入**：只留在会话列表里、当前没打开/运行的旧会话（含同名 fork）不占这 3 个名额。
- **2026-11-02 实测**：工作区会话总数为 **25 个**（kernel `/session` 元数据，含 experience-manager、派单 payload、项目分析等历史会话），但该接口**不提供运行态标记** ⇒ 靠它无法判断谁占着 3 个名额。
- **处置**：在会话列表里关掉不再需要的会话（同名 fork 优先关），保留主线会话后重试；关闭会话**不影响代码**，也不影响 W-D2/L2 进度。

**Why:** 用户看到这条报错时不知道含义，容易误判成环境故障、反复重试，或以为是自己操作错了；把它当成任务失败会误导后续判断。

**How to apply:**
- 见到该报错先**解释含义**（同一工作区活跃会话数上限 3，历史会话不算），再给处置步骤（关 fork）。
- 不要用「工作区有多少会话」推断是否超限——超限看的是**活跃**数，不是总数。
- 派单/开新会话前留意这条限制；双会话并发改同一工作区的风险另见 `feedback_delivery_outcome_semantics.md`。
