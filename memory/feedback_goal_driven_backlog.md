---
name: 按用户既定目标反推应做项，而非并列可选项
description: 用户已给出明确目标时，应从目标逐条反推应落地项并给出「目标↔项↔依据↔优先级」映射；禁止退回到并列的「你可以选 1/2/3」式可选项
type: feedback
from: Agent
---

当用户在请求里**已经明确了目标**（例如「配置信息一致 + 链接 + 实时同步」），回答应直接给出**从该目标反推出来的应做项清单**，并标注每项「对应哪个目标 / 真证依据 / 优先级」；不要把结论包装成若干并列的可选项让用户自己挑。

**Why**: 2026-10-22 双 Agent 配置核查中，我给出的是「1/2/3 三个可选方向 + 需要我进一步做哪一项」，用户随即反问「根据我提出的目标应该做哪些项」——说明并列可选项没有回答用户真正的问题。用户要的是「目标已定，请给出达成它所需的完整清单与优先级」，选项化回答把判断责任又推回给了用户。

**How to apply**:
- 触发条件：用户请求里含明确的成功标准、关键词约束或多目标并列。
- 正确形态：目标逐条 → 应做项 → 依据（真证/文件/命令）→ 优先级（P0/P1）；并区分「硬需求」与「连带收益」。
- 仍需保留「待验证点 / 不可裸承诺」段落，但应放在应做项之后作为风险提示，而非用来替代清单。
- 同类场景（收口计划、待办拆解、回归清单）一并适用：目标明确时不要问「你想先做哪个」。
