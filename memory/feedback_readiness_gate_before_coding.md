name: 动手实现前给「按线就绪度判定」，不给全局二元答案
description: 用户会追问「是否已具备动手条件/是否还需更多实测」；期望按工作线分别判定就绪度，并逐项列出还差什么、类型、阻塞面，最后给二选一授权而非直接开干
type: feedback
from: Agent
---

当用户问「现在具备动手干的条件了吗？是否还需要更多实测再动手？」时，**不要**回答一个全局的「可以 / 还不行」。应把待办**按工作线拆分**，逐线给就绪判定（✅ 可动手 / ❌ 差哪几项），并对每个欠项标明**类型**（实测 / 口径确认 / 现场核对）与**阻塞谁**，最后以「二选一」请用户授权推进顺序。

**Why**: 2026-10-22 双 Agent 配置同步任务，用户在我给出实测结论后追问就绪度。真实情况是「规则线已闭环、记忆线还差 1 项实测 + 1 项口径」，若只回「还不能动手」会白白阻塞可立即推进的部分；若只回「可以动手」则会在记忆线方案形态（单向镜像 vs 双向）上押注未拍板的前提。

**How to apply**:
- 判定前先补现场证据：分支是否被其他进程切换、与 `origin/main` 的差异、是否已有同主题产物或实现（避免重复劳动）。
- 已证可行且无阻塞项的线要**明确授权立即推进**，不要与未就绪的线打包等。
- 沙箱内取不到真证的实测要显式标为「需非沙箱重跑」并给出可直接复制执行的命令与**可判定的成功标志**（如命中特定 token），不要含糊成「待验证」。
- 口径类决策（如同步方向）标为「需你拍板」，不要替用户默认。
