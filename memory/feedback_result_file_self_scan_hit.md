派单结果文件（`collaboration/results/RESULT-*.md`）以及任何写进仓库的说明性文档，若需要**描述扫描规则本身**（触发串、正则片段、示例密钥形态），会出现自命中：扫描器把文档里的这段文字当成待检内容，计数降不到 0。

**处理方式**：把触发串改写成**间接描述**（说明"检测某类前缀 + 固定后缀的组合"这类语义描述，而不是内联可被匹配的原文），必要时配合白名单**自豁免**条目，然后**重新扫描**确认计数归零。

**Why:** 2026-10-24 收口 `TASK-P1-HEALTHCHECK-TOOL-HARDEN-001` 时，结果文件里为说明扫描器行为而内联了触发串，扫描结果出现自命中行，导致"误报 237 条降到 0"的验收口径无法满足；改写描述并复扫后才归零。扫描器只做模式匹配、不理解语义——"写文档说明触发串"这个动作本身就制造了触发串，这与该工单要消除的密钥扫描器误报是同一个根因。

**How to apply:**
- 写结果文件/文档时，凡涉及引用扫描规则、密钥形态、正则片段，一律用间接描述，避免原样内联可匹配文本。
- 写完立刻对结果文件本身跑一次自扫（找出自命中行），确认计数为 0 再进入契约校验与 ACK 环节。
- 与 `feedback_result_file_contract.md`（结果文件四段 + 状态行 + 测试结论）并行遵守；结果文件既要**契约合格**，也要**扫描干净**。
