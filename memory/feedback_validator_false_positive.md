当内置校验器/编辑器诊断对结构化文件（YAML/JSON 等）报错时，**先不要改文件**。应先用权威解析器独立复核（如 Python `yaml.safe_load`），确认是真错还是校验器自身故障；核实为误报后保持文件原样，仅记录校验器不可信。

**Why:** 2026-10-22 接入 `.github/workflows/nightly.yml` 时，编辑工具报告 YAML 结构/缩进错误；读回文件确认缩进与结构合法，随后用 Python yaml 权威验证通过（10 step，两个新增挂载正确）。若当时按报错"修"文件，反而会把本已正确的 workflow 改坏。此模式与本项目既有教训一致：先跑真证命令摸底再判断，区分「洞察 vs 真证」。

**How to apply:**
- 适用于：工作流/配置文件格式校验、schema 校验器、lint 工具的自定义诊断规则。
- 判定顺序：① 读回文件原文人工看结构 → ② 用权威解析器/运行器实际加载 → ③ 只有确证有错才编辑。
- 若最终确认为工具误报，明确向用户说明"报错系校验器误报、文件本身合法"，不要沉默地按报错改动。
- 同一批次内的其他校验（如 json 合法性、git 状态）也应以真实命令输出为准。
