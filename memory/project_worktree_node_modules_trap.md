**仓库里被 git 跟踪的 node_modules 只有约 129 个文件（约 5.3MB），而完整依赖约 71MB / 2600 文件。** 后果链：

1. `git worktree add` 会把这份残缺依赖一起检出，看起来 node_modules 已存在；
2. `npm` 据此误判依赖已安装，不执行安装；
3. `npm run build` 于是报一堆与真实原因无关的错（而不是提示"请先 npm install"），极易被误判为代码或构建脚本的问题。

**Why:** 2026-11-03 在 worktree 里做扩展构建时踩到；补齐依赖后构建才 5/5 全过。这是仓库长期跟踪 node_modules 的结构性副作用，任何用 worktree / 干净克隆做构建的地方都会再遇到，不是临时状态。

**How to apply:**
- 在新 worktree 或新克隆里跑 `npm run build` 前，先核对 node_modules 的文件数/体积是否接近完整量级；异常先补装依赖再归因于代码。
- 报告构建失败时先排掉这个假象，别把依赖残缺的症状当根因。
