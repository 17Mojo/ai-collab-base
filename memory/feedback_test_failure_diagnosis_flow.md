2026-11-09 项目体检中发现 **4 个测试失败**，根因均为"测试断言未对齐新架构"而非产品缺陷：

**失败模式：**
- `test_pack_storage_manager_exists`：断言 `pack-storage-manager.js` 存在，但该文件已被删除（新架构不再使用）
- `test_default_packs_registry`：断言 `default-packs.js` 不存在，但工作区有新增文件（未提交的 N11 功能）
- 其他 2 个失败均为同一类根因的连锁反应

**诊断流程：**
1. 先读测试文件理解断言意图
2. Glob 实际文件结构确认现状
3. 区分"产品缺陷"与"测试未对齐新架构"
4. 对后者，修改测试断言对齐新架构，而非恢复旧文件

**修复策略：**
- 测试断言对齐当前实际文件结构
- 工作区未提交改动（新文件/修改）需先决定提交策略
- 修复后重跑全量测试验证

**Why:** 测试失败不一定是产品缺陷，"测试未对齐新架构"是常见假失败类型；误判为产品缺陷会导致错误修复方向

**How to apply:**
- 遇到测试失败时先诊断根因类型，不要直接改产品代码
- 区分"真失败"（产品行为不对）与"假失败"（测试/环境/架构不对齐）
- 假失败的修复方向是"对齐测试与现状"，而非"恢复旧状态"
