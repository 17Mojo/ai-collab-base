验证「配置/记忆同步」类改动时，静态证据不够，必须补行为级与漂移双向闭环：

1. **静态接线**（文件存在、`CLAUDE.md` 含 `@memory/MEMORY.md`、`AGENTS.md` 4 行逐行精确命中）只是**必要条件**，不能当结论。
2. **行为级验证**：用真实消费方发起一次调用（如 `claude -p "列出 memory/MEMORY.md 中 Feedback 条目标题"`，看模型能否正确复述条目标题数与内容），才算加载真的生效。
3. **漂移双向闭环**：既要验「检测」（人为篡改 → `--check` 返回非 0），也要验「修复」（跑 sync → `--check` 回 0）；只验一边等于没验。
4. **沉淀为可复用脚本**：把上述检查收进一个可重复执行的脚本并报告 `pass/fail` 计数与退出码，便于后续回归而不是一次性手跑。

**Why**: 2026-10-22 双 Agent 配置同步交付后，用户只说了「做一次验证测试」。我把 9 项（静态接线 + 行为级 + 漂移检测 + 漂移修复）逐项列出并给出真证命令，验证全绿；其中 `@import` 的静态接线 PASS 但若无行为级复述，无法排除「文件在但没被加载」。该形态也与用户一贯的「先核对真证、禁止裸数字、声明口径」偏好一致。

**How to apply**: 任何涉及链接、导入、同步、hook 接线的改动，交付后主动补：静态接线 → 行为级 → 漂移检测 → 漂移修复 → 可复用脚本 + `pass/fail` 计数；结论附口径（核验日 / 分支 / 分母 / 版本 / 依据命令），并显式列出仍未决项（如未装 cron、未提交、需重启才可验的项）。
