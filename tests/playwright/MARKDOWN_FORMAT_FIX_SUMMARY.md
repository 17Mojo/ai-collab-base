## 一、问题说明

收到 MD029/ol-prefix 错误提示,表示 Markdown 文档中有序列表项前缀格式不正确。

**错误信息**:
```
MD029/ol-prefix: Ordered list item prefix [Expected: 1; Actual: 4; Style: 1/1/1]
```

**问题原因**:
在同一个文档中存在多个独立的有序列表,每个列表都从 1 开始编号,导致 Markdown 解析器认为编号不连续。

## 三、修复原则

### 3.1 何时使用有序列表

✅ **使用有序列表的情况**:
- 文档中只有一个独立的列表
- 列表项有明确的顺序依赖
- 需要强调序号的列表

示例:
```markdown
### 演示 1: Popup 加载和显示
**执行步骤**:
1. ✅ 创建测试 Pack 数据
2. ✅ 安装 Chrome Host Mock
3. ✅ 导航到 Popup 页面
4. ✅ Popup 页面加载完成
5. ✅ 截图已保存
```

### 3.2 何时使用无序列表

✅ **使用无序列表的情况**:
- 文档中有多个独立的列表
- 列表项之间没有顺序依赖
- 只是为了列举项目

示例:
```markdown
### 演示 2: Pack 列表渲染和选择
**执行步骤**:

- ✅ 安装 Chrome Host Mock
```

## 五、最佳实践建议

### 5.1 Markdown 列表规范

1. **避免在同一个文档中使用多个独立的有序列表**
   - 如果必须使用,考虑使用无序列表
   - 或者使用标题来分隔不同的列表

2. **有序列表应该在整个文档中保持连续**
   - 如果需要重新开始编号,使用无序列表
   - 或者使用不同的标题级别

3. **无序列表更适合列举项目**
   - 不需要强调顺序
   - 更容易维护和修改
   - 不会出现编号不连续的问题

### 5.2 代码示例

**好的做法**:
```markdown
### 任务列表

- 任务 1: 实现功能 A
- 任务 2: 实现功能 B
- 任务 3: 实现功能 C

### 优先级

- 高优先级: 任务 A
- 中优先级: 任务 B
- 低优先级: 任务 C
```

**不好的做法**:
```markdown
### 任务列表

1. 任务 1: 实现功能 A
2. 任务 2: 实现功能 B
3. 任务 3: 实现功能 C

### 优先级

4. 高优先级: 任务 A  ❌ 编号不连续
5. 中优先级: 任务 B
6. 低优先级: 任务 C
```
