# 外部用户试用会话 · 操作指南（W-D2）

> **这份东西给谁看**：给**我们**（主持人 / 观察者）。
> 给外部用户看的是 [`EXTERNAL_USER_ONBOARDING.md`](EXTERNAL_USER_ONBOARDING.md)（一页说明书），
> 记录格式在 [`collaboration/results/external-user/`](../collaboration/results/external-user/)。
>
> **一句话**：这份手册把 2026-10-26 排演（W-D1）攒下的材料，
> 变成一场**可以照着跑完**的真人外部用户会话。

---

## 0. 这份东西是什么 / 不是什么

| | |
|---|---|
| **是** | 一场外部用户会话的**操作手册**：准备什么、交付什么、现场怎么看、最后写什么 |
| **不是** | 用户说明书（那是 `EXTERNAL_USER_ONBOARDING.md`） |
| **不是** | 记录模板（那是 `collaboration/results/external-user/TEMPLATE.md`） |
| **不是** | 排演（排演由我们自己扮演外部用户，**证明不了真人会用**） |

### 为什么排演不能代替这一场

排演查出的 6 个断点里，有 **5 个**在模拟层矩阵与真机 L1 探针里**全都是绿的**——
因为那些测试守的是「我写的那些断言」，而这一场守的是
「**用户实际会走的那条路**」。这两件事的覆盖面根本不同。

更要紧的是：排演者**能读源码**，所以排演只能证明「材料与代码自洽」，
**证明不了「一个真人读得懂、做得下去」**。

路线 A / B 的决策门禁缺的正是这一环（见 [`REAL_MACHINE_REGRESSION.md`](REAL_MACHINE_REGRESSION.md) §7），
所以这一栏的记录**不能由我们自己代写**。

## 1. 这一场同时干两件事（别浪费机会）

| 目标 | 需要什么 | 这一场怎么顺带拿到 |
|---|---|---|
| **W-D2**：第一个真人外部用户 | 一个没用过这产品的人，照着说明书做 | 试用者本人 |
| **L2 第 1 轮**：真实发送 + 等回复 | **人在机器前登录并点发送** | 试用者本人（他在第 5 步就会点） |

⇒ **同一场会话，两份证据**：
试用者的主观反馈（人证）＋ 观测器抓的机器时间线（机证）。

> 观测器 `l2-send-observer.mjs` **不注入文本、不点发送**——
> 发送动作由试用者本人完成，脚本全程只读 DOM，并行跑生产代码里的 `waitForResponse`。
> 这是「探针永不发送」这条红线的唯一合法例外形式：**发送是人做的**。

## 2. 角色分工（一场两个人）

| 角色 | 是谁 | 做什么 | **不**做什么 |
|---|---|---|---|
| **主持人** | 我们 | 准备材料、说开场白、计时、旁观、记录、收尾 | **不替对方操作**、**不提示**、**不解释** |
| **试用者** | 外部人 | 照着说明书一步步做 | —— |

> **铁律：主持人一开口帮倒忙，这场就作废。**
> 我们太熟 ⇒ 我们读得懂说明书；**真人读不懂**才是我们要测的东西。
> 对方卡住时，先在心里数到 30，多数时候对方自己就走过来了——
> 忍不住而伸手的那一刻，你就亲手把这次证据作废了。

## 3. 前置准备（主持人，T-1 天做完）

### 3.1 选人

| 要求 | 说明 |
|---|---|
| **没用过这个扩展** | 用过的人不算；团队成员**不算** |
| 能装 Chrome 扩展 | 会点「加载已解压的扩展程序」；不会就现场教——但**教到这一步为止** |
| 有那个 AI 网站的账号 | 自己注册也行；**账号额度是他自己的**，我们不报销也不代付 |
| **愿意按说明书做、不看我们的聊天** | 提前说清：中途不要来问我们 |

### 3.2 选平台与界面语言

优先 **千问**（我们对它的页面结构查得最细）＋ **中文界面**。
想一次多拿一份证据就加 **Gemini 英文界面**——
但**一次只跑一个平台**，两个平台连着跑会把「哪个平台的问题」搅在一起。

> 界面语言不是我们能指定的：真实站点按 IP 地区决定。
> 观测器会记下**实际观察到的**界面语言（`verdict.observedLanguage`），
> 所以「这一轮跑的到底是什么语言」有据可查，不靠参数推断。

### 3.3 构建扩展（我们做，不让试用者做）

```bash
cd chrome-extension
npm install
npm run build          # 必须看到 === Build Complete ===
```

产物在 `chrome-extension/dist/`——**这就是要交给试用者的那个文件夹**。

### 3.4 环境自检（**在邀请试用者之前**先自己跑一遍）

```bash
cd chrome-extension
node tests/real-machine/dom-contract-probe.mjs \
  --platform=qianwen \
  --profile-dir=/tmp/rm-profile \
  --out=../collaboration/results/real-machine-runs/evidence/L1-precheck-qianwen-<日期>.json
```

> `--profile-dir` 指向**已登录**的持久 profile——没登录态的话探针只会撞登录墙，
> 那个结论对「试用者能不能跑通」没有任何参考价值。
> `--out` 让证据落盘可机检（不写的话这一轮的结论只在终端里，看不见也存不住）。

读法（`outcome` 取值以探针源码为准）：

| outcome | 含义 | 怎么办 |
|---|---|---|
| `pass` | 生产 adapter 在真实站点上还找得到输入框 | 继续 |
| `login_wall` / `bot_check` | 环境限制，**不算缺陷** | 换个已登录的 profile，或改平台 |
| `no_composer` | 到了页面但找不到输入框 | **算失败**：先修，别把坏环境交给试用者 |
| `detect_failed` / `adapter_probe_error` / `adapter_build_failed` | adapter 自己没跑起来 | **算失败**：这是我们的代码问题，不是站点问题 |
| `unreachable` | 站点根本没打开 | **算失败**：网络或 profile 问题 |

> 这一步是**保护试用者**：别让人家的第一次体验消耗在「我们自己的环境是坏的」上。
> 探针**只读**（不注入、不点击、不发送），所以这一步没有副作用。

### 3.5 打包交付物

交给试用者的**只有这些**：

```
交付包/
├── 说明书.pdf（或 .md）        ← docs/EXTERNAL_USER_ONBOARDING.md
├── 扩展/                        ← chrome-extension/dist/ 整个文件夹
└── 冒烟自检 Pack.json            ← packs/examples/external-user-smoke.json
```

**不要给的**：

| 不给 | 为什么 |
|---|---|
| 整个仓库 | 给他代码，他就从「用户」变成「开发者」，测不到说明书 |
| 6 个缺陷的清单 | 知道坑在哪就会绕过去 ⇒ 测不到「材料是不是自洽」 |
| 内部脚本、台账、记忆文件 | 与他要做的每一件事都无关，只会制造噪音 |
| **任何提示** | 「记得先登录哦」这类话会**消灭**我们要观察的那类卡点 |

## 4. 现场流程

### T+0 · 开场白（主持人念，约 1 分钟）

> 「这是一个刚做出来的 Chrome 扩展，能替你把一段固定的话发给 AI 网站。
> 我想请你**照着这份说明书**从头做一遍。
> 三个约定：**卡住了先别问我**，自己试试看；**做不下去就停下**，那不是你的问题；
> 最后我会问你三个问题。」

然后把交付包给他，**计时开始**，之后**闭嘴旁观**。

### T+2 起 · 5 步旁观表

试用者照着说明书做，主持人对照这张表**看**（不是替他做）：

| 步骤 | 说明书里写的成功标志 | 主持人眼里要看的 | 出问题就记 |
|---|---|---|---|
| 1 · 编译 | `=== Build Complete ===` | 我们已构建好 ⇒ **这一步跳过**，直接进第 2 步 | 〔见 §5 的 D0〕 |
| 2 · 装进 Chrome | 扩展列表出现「AI Collab System - Prompt Pack」 | 他有没有找错目录（选了 `dist` 里的文件而不是文件夹） | D1 |
| 3 · 打开网站 | 页面正常、能对话 | 他是不是**先开网站后装扩展**（页面里没有扩展） | D2 |
| 4 · 导入 Pack | 状态栏显示 `导入成功: 1 个 Pack` | 他有没有选错文件；状态栏停住的是不是「导入成功」 | D3 / D4 |
| 5 · 跑一次 | AI 回复里**包含**「你好，Prompt Pack 冒烟自检通过。」 | 提示词**进了输入框**吗？**发出去了**吗？**等到了回复**吗？ | D5 / D6 / D7 |

### T+? · 并行跑观测器（主持人自己操作，不告诉试用者）

在试用者进行第 3～5 步**之前**，另开一个终端跑：

```bash
cd chrome-extension
node tests/real-machine/l2-send-observer.mjs --i-will-send \
  --platform=qianwen \
  --profile-dir=/tmp/rm-profile \
  --wait-for-login \
  --out=../collaboration/results/real-machine-runs/evidence/L2-wd2-qianwen-<日期>.json
```

- `--i-will-send` 是硬闸门：没有它脚本拒绝启动。
- `--wait-for-login`：脚本会等试用者登录（**登录也在这个浏览器里完成**，
  浏览器从头到尾只开一次——cookie 不必在「关—开」之间落盘，那一步不可靠）。
- 脚本**只读**：给页面打 `data-probe-role` 标注之外不改页面，**绝不点发送**。
- 试用者在第 5 步点发送时，脚本正好在并行跑生产 `waitForResponse` ⇒
  产出一份**可机检的 JSON**，而不是一张截图。

### T+end · 收尾三问

按说明书第 5 节问（**原样问，别加提示**），试用者自己写/口述，主持人记。

### T+end · 散场

- 记录当场整理成 `EXTERNAL-USER-<名字>-<YYYY-MM-DD>.md`（用 `TEMPLATE.md`）。
- 截图：含时间戳，聊天内容**先遮住**再放。
- **别当场判「成功/失败」**——判据见 §7。

## 5. 静默观察清单（把排演的 6 个断点变成「盯着看」的动作）

这 6 条是排演查出来的、**已经修好**的断点。它们的**外部可见症状**就是这一列——
主持人**盯着这些症状**，如果又出现，说明修复没生效或站点改版了。
**不要告诉试用者**这些症状的存在。

| 编号 | 已修的断点 | 外部用户身上会长什么样 | 记什么 |
|---|---|---|---|
| **D0** | 我们没构建就交给人 | 他卡在「跑 npm」上 | 换成预构建交付包；本次不算他卡住 |
| **D1** | manifest 漏 `www.` 变体 | 扩展在真站上**完全不出现**（图标灰的、页面里没反应、且不报错） | 站点 URL + Chrome 版本 |
| **D2** | SW 里调页面侧 `detect()` | 弹窗里「没有适配器」/ 执行时报「No adapter available for this page」 | 原文抄下来 |
| **D3** | 前端导入闸门比后台严 | 导入时弹「文件格式错误: 无效的 Pack 导入格式」（而他选的文件**是对的**） | 原文 + 他选的文件名 |
| **D4** | 导入成功标志被冲掉 | 状态栏闪过「导入成功」后变成「已加载 N 个 Pack」 | 他以为导入成功了吗？ |
| **D5** | 失败被跨层吞掉 | 弹窗显示「执行成功」但页面上**什么都没发生** | 「成功」两个字 + 页面实际状态 |
| **D6** | 注入没进编辑器模型 | 输入框里**有字**，但发送按钮**是灰的**、点不动 | 截图（含按钮） |
| **D7** | 等待回复的条件不对 | 提示词发出去了，但 AI 一直没回 / 一直转圈 | 他等了多久 |

> **D6 要特别盯**：它对用户来说最像「我按了没反应」，
> 而对开发来说最容易误判成「用户没点对」。
> 症状是「框里有字 + 按钮灰的」——**只要看到这个组合，就是我们的问题**。

## 6. 记录怎么写

用 [`collaboration/results/external-user/TEMPLATE.md`](../collaboration/results/external-user/TEMPLATE.md) 复制一份，
文件名 `EXTERNAL-USER-<名字>-<YYYY-MM-DD>.md`，放进
[`collaboration/results/external-user/`](../collaboration/results/external-user/)。

字段口径见同目录 [`README.md`](../collaboration/results/external-user/README.md)。三条最容易写错的：

1. **「卡在哪一步」用问卷选项字母**（A～F），别自己改写选项的含义。
2. **「实际做到了哪一步」照实写**——「发出去了，等了大约 40 秒没反应」，
   不要写成「发送失败」（你并不知道它失败没失败）。
3. **报错原样抄**，不要转述、不要美化、不要去掉前缀。

### 隐私红线

- 记录里**不写**账号、密码、手机号、邮箱、公司名。
- 截图里出现聊天内容的，**先遮住**再放进来。
- 试用者自己的聊天内容**不要**粘进记录——只描述「发生了什么」。

## 7. 判定口径与收口

### 7.1 什么算「跑成」

| 结论 | 条件 |
|---|---|
| **完成** | AI 那边**真的回话了**，且回复里**包含**「你好，Prompt Pack 冒烟自检通过。」 |
| 只是「提示词发出去了」 | **不算**完成（那是 D 类） |
| 一次就成功 | 要**特别写清楚**——我们至今没在真机上跑通过整条链路，一次成功本身是**待核实的异常**，不是「没问题了」 |

### 7.2 跑完之后（主持人的活）

1. 把记录放进 `collaboration/results/external-user/`。
2. 把观测器的 JSON 登记进真机回归记录。

   > **`record` 要求那份 run 已经存在**（它只往已有记录里加条目，
   > 没有就报错「记录不存在（先跑 init）」）。
   > 用**已经跑过 L1 的那份**——`RMR-2026-10-26-01` 里已经有 qianwen 的
   > L1 `pass` 和 L2 `not-run` 两条，重登记会**就地替换**那条 `not-run`：

   ```bash
   python3 scripts/real_machine_regression.py record \
     --run-id RMR-2026-10-26-01 --layer L2 --platform qianwen --locale zh-CN \
     --status pass \
     --evidence "真人外部用户跑通整条链路" \
     --evidence-file collaboration/results/real-machine-runs/evidence/L2-wd2-qianwen-<日期>.json
   ```

   > **为什么必须是这份已有 run**：`verify` 有两条硬规则——
   > 「平台 X 缺 L1 记录」与「L2 记为 pass，但 L1 没有 pass 的记录」。
   > 另起一份新 run 只登记 L2，`verify` 会直接报错。
   >
   > **跑完立刻对账**：`python3 scripts/real_machine_regression.py verify --run-id RMR-2026-10-26-01`
   > （退出码 0 = 一致且跑完；2 = 一致但仍有平台没跑完——**这一场只覆盖一个平台，
   > 拿到 2 是正常的**，别把它当成失败）。

3. 记录里暴露了产品缺陷 ⇒ **另开工单**，不要直接改代码。
4. 在 [`REAL_MACHINE_REGRESSION.md`](REAL_MACHINE_REGRESSION.md) §6.2 更新缺口 #5 / #13，
   并附上记录的路径。

### 7.3 门禁怎么变

- `scripts/real_machine_regression.py` 的 `verify` **永远不会**把路线门禁判为关闭
  ——它明说「第一个外部用户」不在它的证据范围内。**这是刻意的**，不要去改它。
- 门禁的关闭条件是**人**给的判断：**有第一份真人记录，且结论够用**
  （真跑通了，或暴露了可修的具体缺陷）。
- **不许提前关**：只有记录存在、且写清楚了，才算这一栏有内容。

## 8. 这一场的红线

1. **不代劳**：不替试用者点任何按钮、不替他改任何文件。
2. **不提示**：不提前说「记得先登录」「先刷新页面」。这些正是我们要观察的东西。
3. **不诱导**：问卷让他自己写，别给选项让他挑。
4. **不代写记录**：记录里的每一句「他的感受」必须来自他本人；
   主持人补的只能是**客观事实**（卡在哪一步、屏幕上的原文、耗时）。
5. **一次一个平台**：两个平台连着跑，出问题时归因会搅在一起。
6. **不碰他的账号**：不登录他的账号、不替他注册、不用他的额度发消息。
7. **不删证据**：失败的会话**也是证据**，照样归档——「真人卡住了」比「没跑过」信息量大得多。

## 9. 一页纸速查（打印出来放桌上）

```
【开始前】npm run build ✓  →  L1 探针自检 pass ✓  →  打包（说明书 + dist/ + Pack.json）
【开场】  "照着说明书做；卡住先别问我；做不下去就停下。"
【过程中】闭嘴、计时、只看不碰。终端另跑 l2-send-observer --i-will-send。
【盯 6 个症状】扩展不出现 / 没适配器 / 文件格式错误 / 成功标志消失 /
                显示成功但啥也没发生 / 框里有字但按钮是灰的 / 发出去了不回
【收尾】  问三问 → 照实记录 → 归档 → 开工单 → 更新台账 → 不提前关门禁
【不许】  代劳、提示、诱导、代写、一次跑两个平台、碰他的账号、删失败记录
```
